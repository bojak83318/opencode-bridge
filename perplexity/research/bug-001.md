## Root Cause Analysis

The `getComputedStyle` error you're encountering is a **known issue in OpenCode AI**. This specific error occurs when the Floating UI library (used for tooltips, popovers, and dropdowns in React applications) attempts to measure DOM elements that haven't fully rendered or have been unmounted during state transitions. [github](https://github.com/anomalyco/opencode/issues/9215)

Based on the stack trace pattern `ho (http://85.121.122.95:4096/assets/index-Bb6jsdVZ.js:1808:15283)`, OpenCode AI uses **React with Vite bundling** and the **Floating UI library** for positioning UI elements like chat input fields and session modals. [zidooka](https://www.zidooka.com/archives/3431)

## Known OpenCode AI Bug Status

This is a **confirmed bug in OpenCode AI** that has been reported multiple times: [github](https://github.com/anomalyco/opencode/issues/8666)

- **Issue #9215**: Directly addresses `getComputedStyle` errors where DOM nodes aren't available during incomplete parsing [github](https://github.com/anomalyco/opencode/issues/9215)
- **Issue #8666**: Windows app version 1.1.21 experiencing identical `TypeError: Failed to execute 'getComputedStyle'` [github](https://github.com/anomalyco/opencode/issues/8666)
- **Recent incidents (Jan 2026)**: Multiple users reported this error immediately after OpenCode updates, with restarts temporarily resolving it [zidooka](https://www.zidooka.com/archives/3431)

The error typically manifests when the `autoUpdate` function from Floating UI calls `getOverflowAncestors()`, which invokes `getComputedStyle()` on a null or unmounted element. [github](https://github.com/floating-ui/floating-ui/issues/2691)

## Nginx Configuration Fixes

Your Nginx reverse proxy setup likely exacerbates timing issues. Apply these specific configurations:

### 1. WebSocket and Upgrade Headers
```nginx
location / {
    proxy_pass http://127.0.0.1:4096;
    proxy_http_version 1.1;
    
    # Critical for WebSocket handshake
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    
    # Preserve original host context
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $host;
}

# Add to http block
map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}
```

These headers are essential because OpenCode's chat sessions likely use WebSocket connections, and missing upgrade headers cause protocol mismatches that lead to DOM synchronization failures. [linkedin](https://www.linkedin.com/pulse/establishing-websocket-connections-role-connection-upgrade-jha-wvubc)

### 2. Disable Proxy Buffering
```nginx
location / {
    # ... existing proxy_pass and headers ...
    
    # Prevent buffering race conditions
    proxy_buffering off;
    proxy_request_buffering off;
    
    # Increase buffer sizes for large payloads
    proxy_buffer_size 256k;
    proxy_buffers 4 512k;
    proxy_busy_buffers_size 512k;
}
```

Proxy buffering can create race conditions in Vite-built SPAs where the frontend attempts to render before the full JavaScript bundle is loaded. [dzone](https://dzone.com/articles/setup-openai-reverse-proxy-with-nginx-for-chatgpt)

### 3. Timeout Adjustments
```nginx
location / {
    # ... existing configuration ...
    
    proxy_read_timeout 300s;
    proxy_connect_timeout 75s;
    proxy_send_timeout 300s;
}
```

## Additional Troubleshooting Steps

### 1. Origin Mismatch Issue
The `opencode serve --hostname 0.0.0.0` command may cause origin validation failures. The frontend expects the API origin to match the browser URL. Verify your Nginx `proxy_set_header Host` uses `$host` (not `$proxy_host`) to preserve the original hostname. [stackoverflow](https://stackoverflow.com/questions/19751313/forward-request-headers-from-nginx-proxy-server)

### 2. Browser Extension Conflicts
**Known problematic extensions** that interfere with `getComputedStyle` in React applications:
- **Dark Reader**: Injects CSS that can invalidate element references
- **LastPass/password managers**: Modify DOM structure in input fields
- **React DevTools**: Can trigger re-renders during measurement

Test in an incognito window without extensions. [github](https://github.com/mui/material-ui/issues/32640)

### 3. Container-Specific Workaround
Since you're using `node:20-slim`, ensure the container has sufficient resources and proper signal handling:

```dockerfile
# Add to your Dockerfile
ENV NODE_ENV=production
ENV OPENCODE_PORT=4096

# Use process manager for proper signal handling
CMD ["opencode", "serve", "--port", "4096", "--hostname", "0.0.0.0"]
```

### 4. Temporary Mitigation
Based on community reports, **restarting the OpenCode service** often clears the error temporarily. This suggests a state initialization bug where the UI attempts to measure elements before the virtual DOM is fully hydrated. [zidooka](https://www.zidooka.com/archives/3431)

## Recommended Action Plan

1. **Apply Nginx WebSocket configuration** with upgrade headers (highest priority)
2. **Disable proxy buffering** to eliminate race conditions
